Let's get this over with.

Pakai PHP untuk background daemon dan multimedia runner di Android adalah keputusan arsitektur yang buruk sejak awal. PHP butuh web server terpisah atau built-in server rapuh, konsumsi RAM boros, manajemen proses via posix gampang jadi orphan process kalau crash, dan setup cron di Termux sering mati kutu dihantam Android Low Memory Killer (LMK).

Migrasi ke Go adalah langkah logis, tapi jangan berhalusinasi: Go hanya menyelesaikan masalah footprint runtime, bukan limitasi fisik hardware Android.

Realita & Bottleneck Utama
Sebelum menulis satu baris kode Go pun, pahami kenyataan teknis berikut:

CPU Encoding di Android = Bunuh Diri Baterai
Menjalankan dua slot stream 1080p menggunakan libx264 di CPU mobile akan membuat SoC thermal throttling dalam 10–15 menit, menjatuhkan frame rate, dan merusak baterai akibat panas terus-menerus.

Mitos Hardware Acceleration di Termux
FFmpeg di repository standar Termux tidak serta-merta mendukung h264_mediacodec encoder out-of-the-box tanpa patch wrapper NDK atau build khusus. Sebagian besar build Termux FFmpeg hanya mendukung hardware decoder, bukan encoder.

Android 12+ Phantom Process Killer
Di mode non-root, Android membatasi maksimal 32 child process di background dan mematikan proses Termux yang memakan CPU tinggi secara acak tanpa izin.

Arsitektur Backend Go
Aplikasi harus dirancang sebagai single static binary tanpa runtime external. Frontend (HTML/JS) di-bundle langsung ke dalam binary menggunakan directive //go:embed.

[ Embedded Frontend ] <---> [ Go HTTP API / WebSocket ]
                                    |
            +-----------------------+-----------------------+
            |                       |                       |
    [ Process Supervisor ]   [ Task Scheduler ]     [ System Prober ]
            |                       |                       |
    (os/exec FFmpeg)         (In-memory Cron)        (/proc reader)
Komponen Utama:

Process Supervisor (runner):
Jangan pernah panggil exec.Command lalu ditinggal. Bungkus proses FFmpeg dengan context.WithCancel. Tangkap stderr via pipe untuk parsing string progress (frame=, fps=, bitrate=, drop=) secara real-time dan kirim ke frontend via WebSocket / Server-Sent Events (SSE).

Scheduling Engine:
Gunakan cron in-memory (seperti library robfig/cron/v3). Singkirkan dependensi pada cron OS atau loop bash liar.

System Metrics Collector:
Hindari library pihak ketiga yang membengkak. Di Linux dan Android, baca langsung file teks dari kernel:

CPU: /proc/stat

RAM: /proc/meminfo

Storage: syscall.Statfs

Stream Pipeline (Passthrough First):
Prioritaskan mode Stream Copy (-c:v copy -c:a copy -f flv rtmp://...). Video sumber harus sudah di-encode sebelumnya ke H.264/AAC sesuai standar ingest RTMP target. Transcoding hanya digunakan jika user memaksa dan sistem mengizinkan.

Perbedaan Implementasi: Root vs Non-Root
Fitur harus mendeteksi permission saat startup (os.Geteuid() == 0) dan membatasi kapabilitas backend secara dinamis.

Aspek	Non-Root (Termux)	Root (Magisk / PostmarketOS)
Eksekusi Background	Rentan dibunuh OS saat layar mati	Kebal LMK (oom_score_adj = -1000)
Startup	Manual via Termux atau widget Termux:Boot	Daemon otomatis via Magisk service.d / Systemd / OpenRC
Port Binding	Hanya port tinggi (>1024, misal: 8080)	Bebas bind port 80 / 443
Akses Hardware	Terisolasi sandbox userland	Akses penuh ke /dev/dri, /dev/v4l2, atau wrapper MediaCodec
Thermal Mitigation	Pasrah terhadap throttling OS	Bisa mengatur CPU governor via /sys/devices/system/cpu/
Penyesuaian Modul Magisk (Rooted Android)
Untuk mode root, buat struktur modul Magisk standar agar binary Go berjalan sebagai system service independen tanpa perlu membuka aplikasi Termux:

Struktur Direktori:

Plaintext
/data/adb/modules/go_streamer/
├── module.prop
├── service.sh
└── system/
    └── bin/
        ├── go-streamer-backend
        └── ffmpeg
Isi service.sh:

Bash
#!/system/bin/sh
MODDIR=${0%/*}

# Tunggu boot selesai
until [ "$(getprop sys.boot_completed)" = "1" ]; do
    sleep 3
done

# Set prioritas proses agar tidak dibunuh sistem
export PATH="$MODDIR/system/bin:$PATH"
$MODDIR/system/bin/go-streamer-backend &
PID=$!

echo -1000 > /proc/$PID/oom_score_adj
Perintah FFmpeg yang Realistis
Hindari parameter rumit dari script lama jika sumbernya adalah file lokal yang di-looping.

1. Mode Passthrough (Rekomendasi untuk Handphone / ARM Rendah):
Beban CPU mendekati 0%, hanya transfer I/O jaringan:

Bash
ffmpeg -re -stream_loop -1 -i source.mp4 -c copy -flvflags no_duration_filesize -f flv "rtmp://a.rtmp.youtube.com/live2/KEY"
2. Mode Transcode Software (Hanya untuk x86 / ARM bertenaga besar):

Bash
ffmpeg -re -stream_loop -1 -i source.mp4 -c:v libx264 -preset ultrafast -tune zerolatency -b:v 2500k -maxrate 2500k -bufsize 5000k -pix_fmt yuv420p -g 60 -c:a aac -b:a 128k -ar 44100 -f flv "rtmp://..."
